# 0004 Static order ticket and direct product copy
Date: 2026-11-02. Authorized by the user's request to remove the hero workflow buttons, retain the order ticket, use T-prefixed table names, and review copy for premium, non-defensive positioning.

## Choice
Keep the open-kitchen visual identity and restaurant photograph, with a static order ticket beside it. Remove the row of workflow stage buttons and its interaction. Use table IDs such as T1–T6 in product examples. Use short, product-specific copy that describes the order and kitchen workflow. Retain concise “illustrative” and “sample” labels wherever imagery, interface, or values are synthetic.

## Rationale
The hero should foreground the POS order details. A control strip beneath the ticket competes with that visual and makes the illustration feel like a demo widget. Clear workflow language describes the product without reassurance claims or generic sales promises.

## Rejected
- The four-stage button row beneath the hero illustration, because it competes with the order ticket and adds interaction that the user asked to remove.
- Removing the sample/illustrative labels, because the scene, interface and amounts are not customer evidence or a live POS screenshot.
- Replacing concrete order and kitchen language with broad claims about trust, ease, or outcomes, because those are not needed to explain the product.

## Consequences
The hero order is a static example. The page describes the order-to-kitchen workflow below the illustration. Table identifiers use a `T` prefix in the interface samples. Necessary notes about sample prices and configured tax remain concise and factual.

## Supersedes
This decision supersedes 0003 only for the interactive hero treatment and its explanatory copy. The open-kitchen identity, palette, typography, and evidence boundaries remain in effect.
